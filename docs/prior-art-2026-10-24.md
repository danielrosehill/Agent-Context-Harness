# Prior-art update: local per-turn "new session?" classifier

Verified: **2026-10-24**, by a Claude Code session (v2.1.310) and two research subagents, using
WebSearch, WebFetch, the Hugging Face API, arXiv abstract pages, `gh search` and the Claude Code
CHANGELOG/binary. It extends [`prior-art.md`](prior-art.md) (2026-10-16) and does not repeat it.

The question, from the 2026-10-24 voice note
([`../context/2026-10-24_auto-session-hook-transcript-raw.txt`](../context/2026-10-24_auto-session-hook-transcript-raw.txt)):
in the **local CLI**, can each user turn be checked automatically ("does this message need the
context so far?") and, if not, be moved into a fresh session, the way Daniel uses `/clear` or
`/new` by hand? And has anyone, Anthropic included, already built that, especially with a
**local model** rather than an API call per turn?

Confidence tags: **Confirmed** = read on the primary source on 2026-10-24. **Secondary** = only
from search summaries or third-party pages. **Inferred** = our reading.

## Verdict

**The gap is open.** Nothing found decides, per turn, "new session or continue" and acts on it,
and nothing found does it with a trained local classifier. Off-the-shelf models for the decision
don't exist either, so a local model has to be fine-tuned for coding-agent sessions.

## 1. What Claude Code itself does (Confirmed)

| Feature | Behaviour | Source |
|---|---|---|
| Idle-return hint, "new task? /clear to save X tokens" | Added in **v2.1.92**: "nudges users returning after 75+ minutes to `/clear`". Purely **time-based**: it doesn't look at the message, and only suggests. Later fixes in 2.1.299 and 2.1.301. Telemetry event `tengu_idle_return_action` in the 2.1.310 binary. | [CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md) lines 389, 554, 6756, 6931 |
| Hooks cannot clear or swap a session | `UserPromptSubmit` can block (`decision: "block"`, `reason`, `suppressOriginalPrompt`), add `additionalContext` and set `sessionTitle`. It "can't replace the prompt". No hook output on any event runs `/clear`, starts a session or runs a slash command. SessionStart `initialUserMessage` only applies in `-p` mode. | [hooks docs](https://code.claude.com/docs/en/hooks.md) |
| Hook timing | `command` hooks on `UserPromptSubmit` default to a 30 s timeout and **block the prompt until they return**; a timed-out hook's output is discarded and the prompt goes through. | same |
| `SessionStart` `source` | `startup`, `resume`, `clear`, `compact`, `fork`. `clear` is what a hook sees after `/clear`. | same |
| Feature requests | anthropics/claude-code **#82658** "automatic context clearing" (closed as stale 2026-09-17), **#68127** auto-clear hook (closed as stale 2026-07-28), **#91836** compact at end of goal (open). | GitHub issues |
| Docs advice | "use /clear … when switching to unrelated work". Manual. | [costs](https://code.claude.com/docs/en/costs.md) |

Claude Code Projects (cloud) routes messages to threads using the coordinator model's judgment;
see the 2026-10-16 scan. It doesn't run in the local CLI and doesn't use a separate classifier.

## 6. Papers

| Paper | Relevance | Confidence |
|---|---|---|
| [CA-BERT, arXiv 2409.13701](https://arxiv.org/abs/2409.13701) | BERT binary "context needed / not needed": the same framing | Abstract confirmed |
| [Beyond Continuity, arXiv 2605.09268](https://arxiv.org/abs/2605.09268) | Pivot vs refine; zero-shot LLMs miss subtle pivots, only some reasoning models do well | Abstract confirmed |
| [AgentPProf, arXiv 2609.20301](https://arxiv.org/abs/2609.20301) | LLM segmentation of coding-agent trajectories; boundary F1 ~0.48, errors mostly over-splitting | Topic confirmed, numbers secondary |
| [DyCP, arXiv 2601.07994](https://arxiv.org/abs/2601.07994) | Lightweight pruner retrieving turn-relevant segments, no fixed boundaries | Abstract confirmed |
| Def-DTS (2505.21033), SuperDialseg (2305.08371), granularity-aware eval (2512.17083) | Segmentation methods and evaluation pitfalls | Secondary |

What this implies (Inferred): the task is hard enough that even frontier models miss subtle
pivots, and the natural failure is **over-splitting**, which is the expensive error here. The
classifier must be tuned for precision on `new_task`.
